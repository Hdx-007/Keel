### 4.3 错误码规范
| 错误码段 | 含义 |
|----------|------|
| 0 | 成功 |
| 40000-40099 | 通用参数错误 |
| 40100-40199 | 鉴权错误 |
| 40300-40399 | 权限错误 |
| 40400-40499 | 资源不存在 |
| 50000-50099 | 服务端错误 |
| 100000+ | 业务模块自定义 |

### 4.4 安全规则
- 密码存储：必须加密（bcrypt/Argon2），禁止明文
- 敏感数据：手机号、身份证等必须脱敏
- 接口鉴权：除登录等公开接口外，所有接口必须鉴权
- 参数校验：所有入参必须做校验
- SQL注入：禁止拼接SQL，必须用参数化查询
- XSS：前端输出必须转义

### 4.5 代码规范
- 缩进：（2空格 / 4空格）
- 行尾：LF
- 代码检查工具：（ESLint / Pylint 等）

## 6. 开发流程规范

### 6.1 分支模型
- `main`：保护分支，始终可发布，只能通过PR合入
- `feature/[模块]-[功能名]`：特性分支，从main拉出，合并即删
- `fix/[问题描述]`：修复分支
- `hotfix/[问题描述]`：线上紧急修复

### 6.2 交付流程
每个MDU必须走完闭环（10关）才能合入：
```
规格确认 → 代码开发 → 单元测试 → 文档同步 → 本地构建通过
→ 测试环境部署 → 自动化测试 → 人工验收 → 合入主干 → 归档沉淀
```
