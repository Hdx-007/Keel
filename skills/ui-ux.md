# Skill：前端UI设计与交互工程（Anti AI Slop）

## 核心问题：为什么AI生成的UI都这么丑和蠢？

AI生成UI有系统性缺陷，业界称为**AI Slop**——298+种可识别的"AI味"模式，主要原因：

1. **没有设计主张**：AI倾向于"安全"选择（Inter字体、蓝紫渐变、圆角卡片、三栏布局），所有网站长得一样
2. **没有视觉层次**：所有东西同等重要，没有主次，没有呼吸感
3. **只画完美路径**：空状态、加载态、错误态、边界数据全部缺失
4. **交互逻辑机械**：按钮点了没反馈、表单校验在提交后才提示、加载无占位、错误无恢复
5. **组件套组件**：Card套Card套Card，三层阴影五层圆角，装饰过载
6. **响应式敷衍**：只在桌面端看起来还行，小屏直接崩

本Skill提供系统化的UI/UX设计工程规范，让AI生成的界面从"能用"到"专业"。

---

## 第一性原理：UI是论点（Thesis），不是装饰

> 参考Emil Kowalski（Vercel Design Engineer）的核心观点：好UI不是"加装饰"，而是"有一个明确的设计主张"。

每个页面/组件在开始写代码前必须回答：
- **这个界面的核心论点是什么？** 用户打开这个页面第一眼应该看到什么？做什么？
- **签名元素（Signature Element）是什么？** 一个让这个界面区别于其他界面的关键视觉/交互元素（不是渐变文字或跳动图标）
- **什么是不必要的？** 能删什么而不影响功能？

**反AI Slop核心铁律**：如果一个元素的唯一作用是"好看"，删掉它。好设计来自于有目的的排版、间距、色彩，而不是装饰。

## Anti AI Slop 黑名单（出现即不合格）

### 视觉Slop（必须禁止）
| 禁止模式 | 为什么丑 | 正确做法 |
|----------|---------|---------|
| 紫→蓝渐变背景/按钮 | 所有AI都选这个，无辨识度 | 选一个品牌主色，或用中性色 |
| 渐变文字标题 | "AI做的"标签，俗套 | 用字号/字重对比建立层次 |
| 通用玻璃拟态（glassmorphism） | 模糊+半透=可读性灾难 | 用纯色/微透明度，模糊只在弹窗/浮层用 |
| 三层以上阴影 | 假立体感，脏 | 最多2层阴影，或干脆用边框/底色分隔 |
| 所有按钮都是大号主按钮 | 没有主次，全是CTA=没有CTA | 一个页面最多1个主按钮，其他用次按钮/文字按钮 |
| 三栏卡片网格（3-card grid） | AI最爱的布局，千篇一律 | 根据内容选择布局：列表/详情/单栏/双栏 |
| 过度圆角（>12px所有元素，>16px仅英雄区大卡片可用） | 幼稚，像婴儿产品 | 按层级：大容器/英雄区12px（最多16px），卡片8px，按钮/输入框6px，标签4px |
| 所有内容居中对齐 | 缺乏视觉引导，阅读困难 | 左对齐为主，居中只用在英雄区/空状态 |
| fade-up滚动动画（所有元素） | 廉价感，分散注意力 | 动画只用于：页面过渡、展开折叠、反馈确认 |
| 装饰性几何图形/点阵/网格背景 | 无意义填充，加载浪费 | 留白本身就是设计 |
| 所有图标都用彩色emoji | 不专业，风格不统一 | 用统一图标库（Lucide/Heroicons），统一线性/填充风格 |
| "Get Started" / "Learn More" 按钮文案 | AI通用文案，无信息量 | 写具体动作："创建项目"、"查看文档"、"连接数据库" |

### 交互Slop（必须禁止）
| 禁止模式 | 为什么蠢 | 正确做法 |
|----------|---------|---------|
| 按钮点了没反应 | 用户不知道是否生效 | 点击立即反馈：loading状态/禁用按钮/成功toast |
| 表单提交后才校验 | 用户填完5个字段才告诉第一个错了 | 实时校验：blur时提示，submit前全量校验 |
| 错误只说"出错了" | 用户不知道怎么办 | 错误说明原因+解决方法："密码至少8位，当前5位" |
| 加载只有一个Spinner | 不知道要等多久，以为卡死了 | 骨架屏+预计时间/进度条；>3秒给取消按钮 |
| 空状态只画个图标 | 用户不知道下一步做什么 | 空状态=引导：图标+说明+行动按钮 |
| 删除无二次确认 | 误操作灾难 | 危险操作必须确认对话框，说明后果 |
| 超长列表无分页/虚拟滚动 | 卡死，找不到内容 | 超过20条必须分页/虚拟滚动/搜索过滤 |
| 弹窗点背景关不掉/没有X | 用户被困 | 弹窗必须可关闭（X/Esc/点背景） |
| Hover效果在移动端不存在 | 移动端无hover，信息隐藏 | 所有hover可见的信息必须有触屏可达方式 |
| 复制成功/保存成功无反馈 | 用户不确定是否成功 | 操作后有明确反馈（toast/状态变化） |

### 专业工具交互Slop（做IDE/编辑器/Figma类产品时必须禁止）
| 禁止模式 | 为什么反直觉 | 正确做法 |
|----------|------------|---------|
| **右键点击没反应** | 在专业工具/编辑器/IDE类产品中，用户右键期望弹出菜单，没反应=坏了 | 专业工具类产品：所有可交互元素/列表项/编辑区必须有右键上下文菜单；营销页/内容站可简化 |
| 没有全局快捷键入口 | 专业用户离不开键盘，没有Cmd+K=玩具 | 提供全局命令面板（Cmd/Ctrl+K） |
| 右键菜单没有快捷键提示 | 用户无法通过右键学习快捷键 | 每个菜单项右侧标注对应快捷键 |
| 右键菜单超过15项/不分隔线 | 找不到想要的操作 | 按功能分组，组分隔线，每组≤7项 |
| 工具栏按钮没有Tooltip（含快捷键） | 鼠标用户不知道按钮干嘛的、键盘用户不知道快捷键 | 悬停200ms显示Tooltip：`操作名 (⌘K)` |
| 可拖拽元素没有grab光标 | 用户不知道能拖 | 可拖拽元素悬停时cursor: grab，拖拽时cursor: grabbing |
| 拖拽时没有插入位置指示 | 不知道会放到哪 | 拖拽时显示蓝色插入线/放置区域高亮 |
| 没有Esc键关闭一切 | 用户按Esc期望关闭弹窗/菜单/面板 | Esc=取消/关闭/返回，全局生效 |
| 选中多个项目后没有批量操作栏 | 多选了不知道能干嘛 | 多选后顶部/底部出现上下文操作栏 |
| 删除后不能撤销 | 误删无法恢复 | 删除后显示toast+"撤销"按钮（5秒内可撤销） |
| 内联编辑点击半天才反应/需要点"编辑"按钮 | 专业工具期望点击即编辑 | 单击即可编辑，Enter/失焦保存，Esc取消 |
| 面板不能折叠/调整大小 | 编辑器/工具类需要灵活布局 | 侧边栏可折叠(Cmd+B)、面板可拖拽调大小 |
| 异步操作阻塞界面 | 用户在保存时不能继续工作 | 乐观UI：本地立即更新→后台同步→失败才回滚 |
| 所有弹层都用居中Modal | 打断心流 | 简单确认用Popover/内联，复杂表单用侧边抽屉 |

## 设计系统规范（Design Tokens）

AI生成UI时必须先建立一套Design Tokens，不能随手写颜色和间距。

### 间距系统（Spacing Scale）
**禁止出现magic number**（13px、17px、23px这种随意数字），必须用4px/8px网格：

```css
/* 允许的间距值 */
--space-1: 4px;    /* 紧密：图标与文字之间 */
--space-2: 8px;    /* 紧凑：相关元素之间 */
--space-3: 12px;   /* 标准：表单项内边距 */
--space-4: 16px;   /* 舒适：卡片内边距、元素组之间 */
--space-6: 24px;   /* 宽松：章节之间 */
--space-8: 32px;   /* 大段：大区块之间 */
--space-12: 48px;  /* 页面：段落之间 */
--space-16: 64px;  /* 页面：大段落之间 */
--space-20: 80px;  /* 英雄区/留白 */
```

### 字号层级（Type Scale）
最多6个层级，不要每个标题都自定义大小：

```css
--text-xs: 12px;   /* 辅助信息、标签、时间戳 */
--text-sm: 14px;   /* 次要文字、说明文字 */
--text-base: 16px; /* 正文、默认文字 */
--text-lg: 18px;   /* 小标题、强调文字 */
--text-xl: 20px;   /* 卡片标题 */
--text-2xl: 24px;  /* 页面标题 */
--text-3xl: 30px;  /* 大标题（少用）*/
--text-4xl: 36px;  /* 英雄区主标题（少用）*/
```

**字号搭配原则**：
- 一个页面最多用3-4种字号
- 标题字重600-700，正文400，辅助文字400
- 行高：标题1.2-1.3，正文1.5-1.6，辅助文字1.4
- 避免用font-weight: 500做"半粗标题"（在Windows系统字体上会模糊）；标题直接用600，正文400；Inter等现代无衬线字体的500可用于按钮文字

### 色彩系统
最多3种颜色+中性色，不要每个元素都用不同颜色：

```css
/* 主色（1个，用于CTA/重点元素） */
--primary: #2563eb;     /* 品牌主色 */
--primary-hover: #1d4ed8;
--primary-light: #dbeafe;

/* 功能色（固定用途，不可他用） */
--success: #16a34a;     /* 成功/通过/在线 */
--warning: #d97706;     /* 警告/需注意 */
--danger: #dc2626;      /* 错误/危险/删除 */
--info: #2563eb;        /* 信息/提示 */

/* 中性色（用明度区分，不要加色相） */
--gray-50: #f9fafb;   /* 页面背景 */
--gray-100: #f3f4f6;  /* 卡片背景、hover态 */
--gray-200: #e5e7eb;  /* 分割线、边框 */
--gray-300: #d1d5db;  /* 禁用边框 */
--gray-500: #6b7280;  /* 辅助文字 */
--gray-700: #374151;  /* 正文文字 */
--gray-900: #111827;  /* 标题文字 */
```

**色彩使用规则**：
- 页面80%是中性色，15%是主色，5%是功能色
- 文字只用gray-700/gray-900/white，不要用纯黑#000
- 不要在彩色背景上放彩色文字（可读性灾难）
- 深色模式不是颜色反转，要重新建立层级（越高的元素越亮）

### 圆角系统
按元素层级，不要一个圆角走天下：

```css
--radius-sm: 4px;    /* 小元素：标签、徽章 */
--radius-md: 6px;    /* 输入框、按钮 */
--radius-lg: 8px;    /* 卡片、弹窗 */
--radius-xl: 12px;   /* 大容器、英雄区卡片 */
--radius-full: 9999px; /* 头像、小圆按钮（仅圆形元素）*/
```

### 阴影系统
定义3种尺寸，单个元素最多叠加2层阴影，禁止层层叠叠堆叠3层以上：

```css
--shadow-sm: 0 1px 2px rgba(0,0,0,0.05);           /* 按钮hover */
--shadow-md: 0 4px 6px -1px rgba(0,0,0,0.1);       /* 卡片、下拉 */
--shadow-lg: 0 10px 15px -3px rgba(0,0,0,0.1);     /* 弹窗、浮层 */
/* 禁止单个元素使用 box-shadow: 0 4px 20px rgba(0,0,0,0.3) 这种重阴影，禁止叠加3层以上 */
```

## 交互逻辑规范（避免"蠢交互"）

### 1. 操作反馈闭环
**每个用户操作必须有即时反馈**：

| 操作类型 | 即时反馈 | 结果反馈 |
|----------|---------|---------|
| 点击按钮 | 按钮pressed态（scale/颜色变化，100ms内） | 成功/失败toast或页面跳转 |
| 提交表单 | 按钮loading+禁用 | 成功跳转/错误提示 |
| 切换Tab | 立即切换+下划线动画 | 内容加载有骨架屏 |
| 下拉选择 | 选项hover态 | 选中后即时更新显示 |
| 删除操作 | 二次确认对话框 | 删除后列表更新+撤销提示 |
| 文件上传 | 上传进度条 | 成功/失败预览 |
| 异步加载 | 骨架屏/loading | 内容展示/错误重试 |

**反馈时间要求**：
- <100ms：感觉即时（按钮点击、hover）
- 100ms-1s：需要loading指示
- 1s-3s：骨架屏+进度提示
- 3s-10s：进度条+取消选项
- >10s：后台任务+完成通知

### 2. 表单交互SOP
- **Label永远可见**：不要用placeholder当label（输入后消失）
- **实时校验**：用户离开字段（blur）时校验，不要等提交
- **错误提示位置**：在对应字段下方，红色文字+具体原因+解决方法
- **必填标记**：用`*`标记必填字段，不要全部标必填
- **提交按钮状态**：表单无效时按钮禁用，提交时按钮loading
- **自动保存**：长表单（>5个字段）自动保存草稿
- **键盘支持**：Tab顺序正确，Enter提交，Esc关闭弹窗

### 3. 状态全覆盖
每个组件/页面必须考虑5种状态，缺一个就是不完整：

| 状态 | 必须包含 |
|------|---------|
| **理想态（Perfect）** | 有数据、一切正常——AI最擅长画这个 |
| **空状态（Empty）** | 无数据时的引导：图标+说明+行动按钮 |
| **加载态（Loading）** | 骨架屏（不是spinner），按最终布局占位 |
| **错误态（Error）** | 出错原因+重试按钮，不要只说"出错了" |
| **部分态（Partial）** | 部分成功部分失败（如批量操作）、权限受限、数据过时 |

### 4. 导航与信息架构
- **面包屑**：超过2层深度的页面必须有面包屑
- **返回按钮**：详情页/二级页必须有明显返回方式
- **当前位置高亮**：导航栏/侧边栏标识当前所在页面
- **标题一致性**：页面标题、导航标题、面包屑标题必须一致
- **URL与页面一致**：URL反映当前页面结构，用户能通过URL理解位置

### 5. 移动端适配
- **最小点击区域**：44×44px（手指大小），不要做12px的小×按钮
- **底部安全区**：iPhone底部手势区域留padding
- **横向滚动谨慎用**：表格/卡片组可以横向滚，但要提示
- **不要依赖hover**：所有hover效果触屏上都看不到，必须有替代
- **键盘弹出**：输入框被键盘遮挡时自动滚动到可见区域
- **字号不小于14px**：iOS会自动缩放小于16px的文字

### 6. 组件8状态标准（每个可交互组件必须交付全部状态）
> 参考Hallmark设计规范：一个交互组件只画default态是不合格的。纯展示组件（Avatar、Badge、Divider等）不需要全部状态。

| 状态 | CSS伪类/场景 | 必须包含的视觉差异 |
|------|-------------|------------------|
| **default** | 基础态 | 基础样式 |
| **hover** | `:hover` | 背景色提升一级，光标变化（pointer/grab） |
| **focus-visible** | `:focus-visible`（键盘Tab聚焦） | 明显的focus ring（outline，不是box-shadow） |
| **active** | `:active`（鼠标按下） | 按下反馈（背景再深一级/scale:0.98/100ms） |
| **disabled** | `:disabled` / aria-disabled | 透明度40-50%，cursor: not-allowed，不可点击 |
| **loading** | 异步操作中 | 按钮内spinner替换文字/显示loading，禁用 |
| **error** | 校验失败/操作失败 | 红色边框/背景，错误提示文字 |
| **success** | 操作成功 | 成功色闪烁/对勾图标，1-2秒后恢复 |

## 桌面级/专业工具交互范式（IDE/编辑器/Figma/Linear类产品）

> 参考VSCode、Figma、Linear、Notion等专业工具的交互模式。如果你在做写作界面、代码编辑器、设计工具、项目管理工具，必须遵守本章。

### 1. 右键上下文菜单（Context Menu）

**在专业工具/IDE/编辑器类产品中，右键没反应 = 产品坏了**。用户对桌面级工具有明确的右键菜单预期。营销页/内容展示站可按需简化。

**标准分组结构**（按顺序，组分隔线分隔）：
```
┌─────────────────────────────────────────┐
│ ① 主要操作（最常用）                      │
│ 打开              Cmd+O                 │
│ 在新标签页打开     Cmd+Shift+O           │
├─────────────────────────────────────────┤  ← 分隔线
│ ② 属性/状态操作                          │
│ 重命名            Enter                 │
│ 移动到...                                │
├─────────────────────────────────────────┤
│ ③ 剪贴板操作                             │
│ 剪切              Cmd+X                 │
│ 复制              Cmd+C                 │
│ 粘贴              Cmd+V                 │
├─────────────────────────────────────────┤
│ ④ 复制链接/导出/重复                      │
│ 复制链接          Cmd+Shift+C            │
│ 重复/克隆          Cmd+D                 │
├─────────────────────────────────────────┤
│ ⑤ 危险操作（红色文字，最后一组）           │
│ 删除              Backspace             │
└─────────────────────────────────────────┘
```

**实现铁律**：
- 单层级≤15项，每组≤7项，超过则用子菜单（`>`箭头指示）
- **不可用的操作显示为灰色禁用态，不要隐藏**（如未选中文本时"剪切"禁用；剪贴板为空时"粘贴"禁用）
- **每个可快捷键操作的项右侧必须显示快捷键**（用于渐进教学）
- 菜单必须完全显示在屏幕内，靠近边缘时自动翻转方向
- **键盘导航**：↑↓导航，→打开子菜单，←关闭子菜单，字母键跳转到首字母匹配项，Enter激活，Esc关闭
- 点击菜单外部区域立即关闭

**不同上下文的菜单差异**：
- 文本选区右键：剪切/复制/粘贴 → 查找"xxx" → 全选
- 文件/项目右键：打开/打开方式 → 重命名/移动 → 复制/重复 → 删除
- 空白区域右键：新建/粘贴 → 排序/视图选项

### 2. 命令面板（Command Palette）

**专业工具的标配**，统一键盘入口。

**激活方式**：`Cmd/Ctrl+K`（macOS用Cmd，Windows/Linux用Ctrl）；VSCode风格可用`Cmd/Ctrl+Shift+P`
```
┌──────────────────────────────────────────────────────┐
│ 🔍 搜索命令、文件或操作...                            │  ← 输入框，打开即聚焦
├──────────────────────────────────────────────────────┤
│ 最近使用                                              │
│   打开文件...                          Cmd+O         │
│   切换主题                             Cmd+K Cmd+T   │
├──────────────────────────────────────────────────────┤
│ 命令                                                  │
│   更改状态                              S            │  ← 助记单键快捷键
│   分配负责人                            A            │
│   设置优先级                            P            │
└──────────────────────────────────────────────────────┘
```

**实现铁律**：
- 模糊搜索（Fuse.js），输入即搜，结果即时返回
- 统一入口：同一搜索框同时搜索命令、文件、内容——用户不需要区分"导航"和"执行"
- 结果排序：最近使用优先，然后是匹配度
- 每项显示：图标 + 名称 + 右侧快捷键标签（`<kbd>`样式）
- 分组显示：最近使用、命令、导航目标，带分组标题
- **助记快捷键**：高频单键操作（S=状态、P=优先级、A=分配），通过命令面板教学
- 键盘导航：↑↓选择，Enter执行，Esc关闭
- 支持Notion式斜杠命令变体：在编辑器中输入`/`触发内联命令面板（插入块/格式化）

### 3. 键盘快捷键与可发现性

**三层快捷键体系**：

| 层级 | 范围 | 示例 |
|------|------|------|
| 平台通用 | 所有应用一致 | Cmd+Z撤销、Cmd+C/X/V复制剪切粘贴、Cmd+A全选、Cmd+S保存、Cmd+F查找 |
| 应用全局 | 整个应用 | Cmd+K命令面板、Cmd+P快速打开、Cmd+B切换侧边栏、Esc关闭/取消 |
| 上下文 | 特定区域 | 编辑器：Cmd+D多光标、Alt+Click添加光标；列表：S改状态、P改优先级 |

**可发现性策略**（关键！用户怎么学会快捷键？）：
1. **右键菜单中显示快捷键**——用户右键时看到，逐步学习
2. **命令面板中显示快捷键**——搜索时右侧标注
3. **Toolbar按钮Tooltip中包含快捷键**——悬停显示 `复制 (⌘C)`
4. **提供快捷键参考面板**——Cmd+K Cmd+S打开可搜索的快捷键列表
5. **平台适配**：macOS显示⌘⌥符号，Windows显示Ctrl/Alt，自动切换
6. **不强制使用**：所有快捷键操作都必须有鼠标可达的替代方式

**全局快捷键铁律**：
- `Esc` = 关闭当前打开的任何东西（弹窗/菜单/面板/命令面板），多层则逐层关闭
- `Cmd+Z` = 撤销，`Cmd+Shift+Z` = 重做（专业工具标准；文本编辑可额外支持Cmd+Y）
- `Tab` = 在UI控件间正向导航，`Shift+Tab` = 反向；工具栏/标签列表内用方向键导航

### 4. 悬停、Tooltip与预览

**悬停状态层级**（参考Linear）：
```css
/* 默认 → 悬停 → 选中 → 按下 */
--bg-default: transparent;
--bg-hover: rgba(255,255,255,0.05);    /* 悬停：背景微升 */
--bg-active: rgba(255,255,255,0.08);   /* 选中：背景再升 */
--transition-fast: 100ms cubic-bezier(0.16, 1, 0.3, 1);
```

**Tooltip规范**：
- 触发延迟：200-400ms（避免鼠标滑过误触发），键盘聚焦时立即显示
- 消失：鼠标离开立即消失，或5秒自动消失
- 内容：简洁操作名 + 右对齐快捷键，如 `复制文本        ⌘C`
- 位置：元素下方/右侧，不遮挡内容，靠近边缘自动调整
- 样式：深色背景+白色文字，8px圆角，小字号(12px)，内边距6px 10px
- 键盘聚焦的元素（Tab到的按钮）也必须显示Tooltip

**悬停揭示控件**（Notion模式）：
- 次要控件（块拖动手柄⋮⋮、行内操作按钮）默认`opacity: 0`
- 悬停在父元素上150ms后淡入到`opacity: 1`
- 减少界面噪音，需要时才显示

**预览模式**（VSCode式）：
- **预览标签**：单击文件在资源管理器中打开时使用预览模式（标签斜体），复用标签；编辑/双击后转为永久标签——防止"快速浏览导致标签爆炸"
- **内联预览（Peek）**：预览定义/引用时，在内嵌编辑器区域展开，不跳转离开当前上下文
- **悬停高亮**：Figma模式——悬停图层面板项目时，画布上对应元素高亮

### 5. 拖放交互（Drag & Drop）

**四种视觉反馈状态机**：

| 状态 | 视觉反馈 |
|------|---------|
| 可拖拽（idle） | 悬停时`cursor: grab`，拖动手柄显示 |
| 拖拽开始（drag start） | 被拖拽元素显示半透明"幽灵"(50-70% opacity)跟随光标，原位置留占位符，`cursor: grabbing` |
| 拖拽经过（drag over） | 有效放置区域高亮；显示插入指示器：水平线（列表重排）或垂直线（面板分割），2px主题色；无效区域显示禁止图标或不高亮 |
| 放置完成/取消 | 成功：平滑动画到新位置(200ms)；取消：弹回原位置动画 |

**实现铁律**：
- 列表/树重排：拖拽时显示蓝色水平线指示插入位置
- 面板分割：拖拽标签到左/右/上/下/中边缘时显示放置区域高亮
- 自动滚动：拖拽到列表/面板边缘时自动滚动
- 键盘替代：提供键盘操作方式（如Alt+↑/↓移动行/项）
- 多项目拖拽：选中多个项目后拖拽保持多选状态

### 6. 多选与批量操作

**多选手势**：
- 连续选择：`Shift+点击` 选中两次点击之间的所有项
- 离散选择：`Cmd/Ctrl+点击` 切换单个项的选中状态
- 框选：按住空白区域拖拽出矩形选框（Figma/画布类）
- 全选：`Cmd/Ctrl+A`
- 取消选择：`Esc` 或 点击空白区域

**多选后UI反馈**：
- 选中多个项目后，**立即出现上下文批量操作栏**（固定在列表顶部/底部）
- 批量操作栏内容：`已选 N 项: [更改状态▾] [分配▾] [删除]`
- 快捷键对多选生效：按S/P/A等直接对所有选中项操作
- 操作后toast反馈："已更新5个issue"
- 支持批量撤销

**多光标编辑**（编辑器类产品）：
- `Alt+Click`：在任意位置添加光标
- `Shift+Alt+↑/↓`：在上方/下方添加光标
- `Cmd+D`：选中下一个匹配项
- `Ctrl+Shift+L`：选中所有匹配项（同时编辑）

### 7. 撤销/重做系统

**标准快捷键**：
- macOS：撤销 `Cmd+Z`，重做 `Cmd+Shift+Z`（Figma/Adobe/现代专业工具标准）；文本编辑场景也可支持 `Cmd+Y`
- Windows/Linux：撤销 `Ctrl+Z`，重做 `Ctrl+Y`（传统标准）；设计类工具可用 `Ctrl+Shift+Z`
- 建议：专业工具/设计软件遵循Cmd+Shift+Z；通用文本编辑两者都支持

**实现规则**：
- **操作合并**：连续同类操作合并为一个撤销步骤（连续打字→一次撤销全恢复；连续拖拽→释放鼠标记录为一步）
- **复合操作原子化**：批量操作（如移动5个图层）作为整体一次撤销
- **撤销栈**：线性撤销（简单可预测，推荐），撤销后新操作清空重做栈
- **乐观UI的撤销**：本地立即撤销→后台发请求→失败重新应用+提示
- **危险操作的撤销窗口**：删除后toast显示"已删除" + "撤销"按钮（5秒内可撤销）
- 撤销栈大小：桌面工具建议100+步

### 8. 状态栏与进度指示

**状态栏**（底部22-24px高，参考VSCode）：
```
┌──────────────────────────────────────────────────────────────────┐
│ ⑂ main*  ⊘ 0  ⚠ 2  │  行12,列8  空格:4  UTF-8  Markdown        │
│ ────────────────────┤                                            │
│ 左侧: 全局/项目状态   │  右侧: 编辑器/光标/上下文信息              │
└──────────────────────────────────────────────────────────────────┘
```
- 低调：低对比度背景，小字号(11-12px)，不主动吸引注意力
- 左右分区：左侧放项目/Git/错误状态，右侧放光标位置/文件类型/语言状态
- 可交互：点击状态项可执行操作（点击错误数打开问题面板）
- 实时更新：反映当前上下文状态

**进度指示层级**：
| 操作范围 | 显示位置 | 样式 |
|---------|---------|------|
| 全局阻塞 | 模态遮罩+中心进度 | 进度条+取消按钮 |
| 后台操作 | 状态栏进度条 | 不阻塞用户工作 |
| 区域操作 | 面板内进度条 | 面板内局部显示 |
| 内联操作 | 元素旁小spinner | 单元格保存、消息发送 |

**进度规则**：
- 已知时长用确定进度条（0-100%），未知时长用不确定动画（条纹/spinner）
- 后台操作采用乐观UI：不阻塞用户继续操作
- 长操作（>3秒）必须提供取消按钮
- 完成后立即消失；错误态进度条变红+错误消息+重试

### 9. 面板与标签管理（IDE布局标准）

**标准六区域布局**（VSCode范式）：
```
┌────┬────────────────────────────────────────┐
│    │  标签栏: [文件1.md ×] [文件2.md ●] [+]  │
│    ├────────┬───────────────────┬───────────┤
│ 活 │        │                   │           │
│ 动 │ 左侧边栏│    主编辑区        │ 右侧边栏   │
│ 栏 │(文件树  │   （可任意方向      │ (大纲/    │
│    │ 搜索   │    分割为多组)      │  Chat)    │
│    │ Git等) │                   │           │
│    │        │                   │           │
│    ├────────┴───────────────────┴───────────┤
│    │  底部面板（终端/输出/问题）               │
├────┴────────────────────────────────────────┤
│  状态栏（整个窗口宽度）                       │
└────────────────────────────────────────────┘
```

**面板管理铁律**：
- 活动栏(Activity Bar)：窄竖条图标切换侧边栏，带状态徽章（如Git变更数）
- 侧边栏可折叠：`Cmd/Ctrl+B`切换显示/隐藏
- 底部面板可拖拽调整高度，可移动到侧边
- 面板间用1px边框分隔，不用阴影/圆角

**标签页管理**（防标签爆炸）：
- **预览标签模式**：单击打开文件→预览标签（斜体标题），复用标签；编辑/双击→转为永久标签
- 修改未保存：标签前显示`●`圆点
- 关闭选项：关闭/关闭其他/关闭右侧/关闭已保存/全部关闭
- `Ctrl+Tab`：在最近使用标签间切换（MRU顺序）
- 支持拖拽标签重排、分割编辑器组、拖出为浮动窗口

### 10. 内联编辑 vs 模态编辑

**决策矩阵**：

| 场景 | 模式 | 触发 | 确认 |
|------|------|------|------|
| 修改标题/名称/状态 | **内联编辑** | 直接单击 | Enter/失焦保存，Esc取消 |
| 块类型转换/插入 | **内联菜单** | 点击⋮⋮或输入`/` | 选择即生效 |
| 编辑正文/内容 | **内联编辑** | 直接点击输入 | 自动保存 |
| 更改属性（状态/优先级/分配） | **内联下拉** | 单击属性值 | 选择即生效 |
| 创建新实体（多字段） | **模态/命令面板** | Cmd+N/按钮 | 提交确认 |
| 填写复杂表单 | **模态/侧边抽屉** | 按钮/链接 | 提交按钮 |
| 系统设置 | **侧边面板/标签页** | Cmd+, | 自动保存/关闭 |
| 删除确认 | **确认对话框/Popover** | Delete键/按钮 | 确认/取消 |

**内联编辑铁律**：
- 点击即可编辑，不需要先点"编辑"按钮
- 光标在点击位置出现
- Enter确认保存，Esc取消恢复
- 点击外部区域自动保存
- 编辑态与显示态视觉差异小（微背景/下划线），防止布局跳动
- 乐观UI：确认后立即更新UI，后台同步

**模态类型选择**：
- **确认对话框**：居中，小，只有确认/取消——用于危险操作确认
- **侧边抽屉**：从右侧滑出，保留部分上下文——用于属性检查、详细编辑
- **居中Modal**：居中遮罩——用于复杂表单、创建实体
- **Popover**：小浮层，附着在触发元素旁——用于简单选择、日期选择

### 11. 乐观UI（Optimistic UI）

> Linear核心设计原则：速度即功能。永远不阻塞用户下一步操作。

**乐观更新模式**：
```
用户操作 → 立即更新本地UI（显示成功状态）→ 后台发送API请求
                                            ↓
                                 请求成功 → 静默确认（无需额外反馈）
                                 请求失败 → 回滚本地状态 + 显示错误toast+重试选项
```

**适用场景**：
- 状态/优先级/分配更改
- 重命名/标题修改
- 复选框勾选/取消
- 收藏/点赞
- 排序/拖拽重排
- 标记已读/未读

**不适用场景**：
- 支付/资金操作
- 删除（需要可撤销窗口）
- 发送消息（需要发送状态指示，但不要阻塞输入）
- 权限不足可能导致失败的操作

**关键规则**：
- 本地更新必须是可逆的（记录前值，失败可回滚）
- 失败时明确告诉用户"操作失败：[原因]，已恢复" + 重试按钮
- 不要显示"保存中..."这种打断式loading，让操作感觉即时
- 提交表单时：按钮进入loading态（因为这是显式提交动作，用户预期等待）

## 代码生成规则（写UI代码时必须遵守）

### 组件设计原则
1. **一个组件只做一件事**：如果组件名里有"And"，拆成两个
2. **Props少而明确**：超过5个props考虑拆分或用compound component
3. **状态在需要的最小组件内**：不要把状态都提到顶层
4. **列表必须加key**：用唯一ID，不要用index
5. **条件渲染清晰**：用早返回(early return)处理loading/error/empty，不要嵌套三元

### CSS/Tailwind使用规则
- **禁止inline样式**（除了动态值如width: ${progress}%）
- **禁止!important**（除非覆盖第三方库且有注释说明原因）
- **用Tailwind的话遵守顺序**：布局→尺寸→间距→颜色→文字→交互
- **响应式mobile-first**：先写移动端样式，用md:/lg:扩展到桌面
- **不要写死宽度**：max-w-*约束最大宽度，让内容自适应
- **图片必须有alt**：装饰性图片alt=""，内容图片写描述

### 可访问性（A11y）最低要求
- 所有交互元素用`<button>`/`<a>`，不要用`<div onClick>`
- 图片有alt属性
- 表单控件有对应的`<label>`
- 弹窗有role="dialog"，打开时焦点 trap 在弹窗内
- 颜色对比度≥4.5:1（AA标准）
- 键盘可导航：Tab能访问所有交互元素

## UI审查清单（Designer角色用）

生成UI后，用以下清单逐项检查：

### 视觉检查
- [ ] 有明确的视觉层次吗？第一眼知道看哪吗？

- [ ] 字号层级是不是≤4种？
- [ ] 圆角是否按元素层级区分？
- [ ] 图标风格统一吗？

- [ ] 表单是blur实时校验吗？

## 反模式（出现必须重构）

3. **CSS-in-JS对象里写了20个style属性**：提取为className/Tailwind类
4. **useEffect地狱**：5个以上useEffect互相依赖——重新思考状态管理
5. **巨型switch case渲染**：用配置映射表
6. **复制粘贴的重复JSX**：提取为组件或map渲染
7. **hardcode颜色/间距值**：用design tokens
