# Skill 04：部署上线与验证

## 阶段目标
按部署规格安全、可控地发布到生产环境，完成冒烟验证与业务验收，确保监控告警生效。

## 准入条件
- 集成测试通过，P0/P1 bug为0
- 所有验收标准验证通过
- 部署文档与配置清单已更新
- 回滚预案已明确并演练过
- 运维、开发、测试人员就位

## 发布前检查清单（必须全部确认）
| 检查项 | 确认方式 |
|--------|----------|
| 代码已合入main分支并打tag | Git tag与版本号一致 |
| 构建产物已生成并验证 | CI构建成功，产物hash可追溯 |
| 数据库迁移脚本已准备 | 迁移脚本已在测试环境验证 |
| 配置文件已更新 | 生产环境配置已检查，敏感配置走环境变量 |
| 回滚预案已明确 | 回滚步骤、责任人、验证方式已确认 |
| 监控告警已配置 | 核心指标、日志、告警规则已就绪 |
| 相关人员已通知 | 产品、客服、运维已知晓发布时间与范围 |

## 执行步骤

### Step 1：发布策略选择
根据影响范围选择发布策略：

| 策略 | 适用场景 | 优点 | 风险 |
|------|----------|------|------|
| 灰度发布（金丝雀） | 核心功能、大版本、用户量大 | 影响范围小，可快速回滚 | 复杂度高，需流量控制 |
| 蓝绿部署 | 非核心功能、有双套环境 | 切换快，回滚简单 | 资源成本高 |
| 滚动发布 | 小版本、bug修复、无兼容问题 | 资源占用少 | 回滚慢，存在中间状态 |
| 停机发布 | 非业务时段、兼容性变更 | 简单可靠 | 服务中断 |

推荐默认使用**灰度发布**，小版本可使用滚动发布。

### Step 2：灰度发布执行（推荐）
1. **灰度1%流量**：
   - 部署到灰度节点
   - 观察5-10分钟：错误率、响应时间、日志异常
   - 核心功能冒烟验证
   - 如有问题立即回滚
2. **灰度10%流量**：
   - 扩大到10%用户
   - 观察15-30分钟
   - 关注业务指标（下单、登录等核心链路）
   - 客服反馈收集
3. **全量发布**：
   - 灰度验证通过后逐步全量
   - 持续观察1小时
   - 确认所有监控指标正常

### Step 3：线上验证
发布完成后立即执行：
1. **测试冒烟验证**：
   - 核心功能主路径验证
   - 关键接口可用性检查
   - 异常场景验证
2. **产品业务验收**：
   - 产品按验收标准逐条验证
   - 业务数据核对
   - 用户视角体验验证
3. **运维监控验证**：
   - 监控大盘检查（CPU、内存、QPS、错误率）
   - 日志检查（无ERROR级别异常）
   - 告警通道测试（可选）

### Step 4：发布后值守
- 发布后2小时内开发、运维在线值守
- 核心时段（如工作时间）持续监控4小时
- 异常按故障等级处理：
  - P0（核心功能不可用）：立即回滚
  - P1（主要功能异常）：快速修复或回滚
  - P2（次要问题）：记录后下个版本修复

### Step 5：发布完成确认
满足以下条件可确认发布成功：
- 所有监控指标在正常范围
- 核心功能验证通过
- 无P0/P1线上问题
- 业务数据无异常波动
- 产品验收通过

## 回滚流程
出现以下情况必须立即回滚：
1. 核心功能不可用
2. 错误率超过阈值（如&gt;1%）
3. 响应时间严重恶化
4. 数据异常（写入错误、数据丢失风险）
5. 安全漏洞

回滚步骤：
1. 发布负责人下令回滚
2. 运维执行回滚操作（按回滚预案）
3. 验证回滚后服务恢复正常
4. 通知所有相关方
5. 记录故障原因，输出复盘报告

- [ ] 监控告警配置（已生效）

## 质量门禁
| 检查项 | 通过标准 |
|--------|----------|
| 核心功能 | 100%可用 |
| 错误率 | ≤0.1%（或符合基线） |
| 响应时间 | 符合性能基线 |
| 监控告警 | 全部配置生效 |
| 数据库迁移 | 执行成功，数据正常 |
| 回滚能力 | 验证过可5分钟内回滚 |

## 常见问题与应对

### Q1：发布过程中发现问题要不要继续？
- P0/P1问题：立即停止发布，回滚
- P2问题：评估影响，可记录后继续或回滚
- 任何犹豫都选择回滚，安全第一

### Q2：数据库迁移失败怎么办？
- 立即停止发布
- 优先恢复数据（从备份）
- 修复迁移脚本，在测试环境充分验证后再发
- 大表变更必须有回滚方案

### Q3：线上问题定位慢怎么办？
- 先回滚恢复服务，再慢慢定位
- 利用TraceId、日志、监控快速定位
- 平时做好可观测性建设，不要等出问题才加日志

## 反模式（禁止行为）
- ❌ 周五下班前发布（没人值守）
- ❌ 不做灰度直接全量
- ❌ 没有回滚预案就发布
- ❌ 发布完就下班，不等观察期
- ❌ 出问题先debug半小时，不回滚
- ❌ 跳过测试验收，开发说没问题就上线
- ❌ 敏感配置硬编码提交到仓库
