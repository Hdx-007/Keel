# Skill 03：联调与集成测试

## 阶段目标
前后端基于真实环境联调，发现并解决契约不一致与逻辑bug，通过集成测试与回归测试，确保功能符合验收标准。

## 准入条件
- 前后端各自单测通过率≥90%
- 接口契约自验证通过
- 代码已部署到测试环境
- 自动化测试用例已准备就绪

## 联调门禁检查（必须全部通过）
| 检查项 | 验证方式 |
|--------|----------|
| 后端单测通过率 | ≥90%，核心业务逻辑必须覆盖 |
| 前端单测通过率 | ≥90%，核心业务逻辑必须覆盖 |
| 契约一致性 | 工具校验字段、类型、路径完全一致 |
| 测试环境可用性 | 服务可正常访问，依赖服务正常 |
| 测试数据准备 | 测试账号、测试数据已就绪 |

## 执行步骤

### Step 1：联调准备
1. 后端将代码部署到测试环境，关闭Mock
2. 前端切换API地址到测试环境
3. 测试团队准备好测试用例与测试数据
4. 建立联调问题实时记录通道（飞书群/在线文档）

### Step 2：接口联调
按模块逐个接口联调：
1. **冒烟验证**：每个接口先调通 happy path
2. **参数校验**：验证必填项、类型、边界值
3. **异常场景**：验证错误码、错误提示是否符合契约
4. **数据一致性**：验证前端展示数据与后端返回一致
5. **权限校验**：验证鉴权逻辑是否正确

### Step 3：问题分类处理
联调发现的问题按以下分类处理：

| 问题类型 | 处理方式 | 责任人 |
|----------|----------|--------|
| 契约不一致（字段名/类型/路径错误） | 先确认契约正确方，更新契约，双方同步修改 | 提出方发起变更 |
| 后端逻辑BUG | 后端修复，回归验证 | 后端开发 |
| 前端逻辑BUG | 前端修复，回归验证 | 前端开发 |
| 需求理解偏差 | 产品确认，走规格变更流程 | 产品牵头 |
| 环境问题 | 运维排查修复 | 运维 |

问题记录规范：
```markdown
### BUG-001
- 模块：用户登录
- 问题描述：密码错误时返回500而非约定的401
- 复现步骤：输入错误密码点击登录
- 预期结果：返回401 + 错误码AUTH_002
- 实际结果：返回500
- 责任人：后端
- 状态：待修复
```

### Step 4：集成测试
联调通过后，测试团队执行集成测试：
1. **功能测试**：按测试用例执行所有功能点
2. **接口测试**：执行Newman/Jest接口自动化脚本
3. **场景测试**：端到端业务场景验证
4. **兼容性测试**：浏览器/设备兼容性（如需要）
5. **性能测试**：核心接口性能基线验证（如需要）

### Step 5：回归测试
bug修复后必须做回归测试：
1. 验证bug确实修复
2. 验证相关功能未被影响
3. 核心场景全量回归
4. 自动化测试全量跑一遍

### Step 6：文档同步更新
联调过程中发现的文档问题必须同步更新：
1. 更新API_SPEC.md（契约修正）
2. 更新部署文档、配置清单
3. 更新MODULE_SPEC.md（如接口有变更）
4. 记录到ERROR.md（如为可复用的经验教训）

## 常见问题与应对

### Q1：联调发现大量契约不一致怎么办？
- 说明开发阶段契约校验没做好
- 暂停联调，双方重新对齐契约
- 增加CI契约校验环节，下次避免
- 记录到ERROR.md作为流程改进点

### Q2：bug修完引入新bug怎么办？
- 必须做相关功能回归测试
- 增加自动化测试覆盖该场景
- 评估代码改动影响范围，扩大回归范围

### Q3：测试环境不稳定怎么办？
- 运维优先保障测试环境稳定性
- 环境问题不计入开发bug
- 建立测试环境健康检查机制

## 反模式（禁止行为）
- ❌ 单测没过就进入联调
- ❌ 问题不记录，口头说改就改
- ❌ 修bug不回归，改完就完事
- ❌ 契约问题只改代码不改文档
- ❌ P0/P1 bug没修完就上线
- ❌ 测试环境连不上就等，不主动排查
